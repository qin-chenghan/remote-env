2 引言

2.1 编写目的

本文档针对 llama.cpp 推理引擎在鲲鹏 ARM 平台上的 CPU 算子性能瓶颈，进行详细的优化设计。llama.cpp 是大模型推理的核心引擎之一，其 CPU 后端的矩阵乘法和注意力机制（SDPA）算子的性能直接影响推理端到端的时延。

文档明确各优化点的功能、算法、接口、实现方案和测试标准，为 llama.cpp 在鲲鹏平台的适配、开发、测试提供统一依据。

5 模块设计

5.1 FP16 矩阵乘法优化

5.1.1 功能描述

FP16 矩阵乘法是 Embedding 模型推理中最频繁的计算模式（模型权重为 F16 时），主要为 prefill 阶段计算。本优化提供了四个层次的 kernel 覆盖不同 M、N 配置：

| # | Kernel | SIMD 风格 | Tile 尺寸 | 适用场景 |
|---|---|---|---|---|
| 1 | vec_dot_f16 | NEON 内积 (点积) | 64 元素流水线 | 通用 dot product fallback |
| 2 | matmul_f16_4x4_kernel | NEON 外积 (vfmaq_f16) | 4×4 tile | prefill 小批量 (M<16) |
| 3 | matmul_outer_8x16_b_micro_packA_f16 | NEON 外积 + 手写 asm | 8×16 tile | prefill 大批量 (M>=16, packA 预打包) |

外积 (outer product) 风格以一个 A 向量的每个标量 lane 广播乘整个 B 向量，与内积 (dot product) 风格按 K 维度累加不同。外积在 M 较大时能更充分地利用寄存器文件和指令级并行。

5.1.2 核心算法

vec_dot_f16 (NEON Software Pipeline)

输入: x[n], y[n] (fp16)
输出: sum = Σ x[i] * y[i]

1. 初始化 8 个 float16x8_t 累加器 (acc0..acc7)
2. 预加载前 64 个元素到 ax0..ax7 / ay0..ay7
3. 主循环 (i = 64; i < np; i += 64):
   acc[k] += ax[k] * ay[k];  // 计算本轮
   ax[k] = vld1q_f16(&x[i+k*8]);  // 加载下一轮 (软件流水线)
   ay[k] = vld1q_f16(&y[i+k*8]);
4. 尾循环处理最后 64 元素
5. vpaddq_f16 水平累加 + vcvt_f32_f16 转 f32 求和

[图片]

matmul_f16 4×4 Kernel (NEON 外积 tile)

输入: A[M,K], B[N,K] (fp16)
输出: C[M,N] (f32)

特点: 4×4 = 16 个 vfmaq_f16 外积累加，fp16×fp16→fp32

1. N==1 fast path: 按 M 行循环，每行一个 vfmaq_f16 累加，避免函数调用开销
2. 4×4 tile 主循环:
   - 加载 A[j..j+3][k..k+8], B[i..i+3][k..k+8]
   - 16 次 vfmaq_f16 (j0×i0..i3, j1×i0..i3, ...)
   - 水平累加 vcvt_f32_f16 + vaddvq_f32 写入 C
3. M 尾循环 (1-3行): 批处理 NEON 避免 vec_dot_f16 开销
4. N 尾循环: vec_dot_f16 fallback

[图片]

matmul_outer_8x16_b_micro_packA_f16 (手写 NEON 外积，prefill 大批量)

输入: packA(预打包A)[M_packed, K], B[N,K] (fp16)
输出: C[M,N] (f32)
约束: M % 16 == 0, N % 8 == 0

特点: 手写汇编，外积 8×16 tile，K 按 32 展开双缓冲

主循环 (N 按 8, M 按 16):
  初始化 16 个 NEON 累加器 (v12..v27)
  K 主循环 (step=32, 双 block):
    加载 16×2 个 A vector (从 packA 中)
    加载 8 个 B vector
    每个 B 向量的 8 个 lane 分别广播乘 16 个 A vector
    → 8 × 16 = 128 次 fmla 外积 (总 256 次/step=32)
  K 全块尾循环 (step=16)
  K 标量尾循环 (step=2)
  fcvtl f16→f32 写回 C

// vec.h
/**
 * 计算两个 fp16 向量的点积，结果累加到 fp32 标量数组中。
 *
 * @param n     向量长度（元素个数）
 * @param s     输出标量数组（fp32），长度为 nrc；每个点积结果累加到对应的 s[bs] 位置
 * @param bs    s 数组的步长：第 i 个点积的结果写入 s[i * bs]
 * @param x     输入向量 x（fp16），长度为 n * bx * nrc
 * @param bx    x 的行步长（元素个数）：第 i 个点积的 x 起始位置为 &x[i * bx]
 * @param y     输入向量 y（fp16），长度为 n * by * nrc
 * @param by    y 的行步长（元素个数）：第 i 个点积的 y 起始位置为 &y[i * by]
 * @param nrc   需要计算的组数（点积条数）
 */
void ggml_vec_dot_f16(int n, float * GGML_RESTRICT s, size_t bs,
                      ggml_fp16_t * GGML_RESTRICT x, size_t bx,
                      ggml_fp16_t * GGML_RESTRICT y, size_t by, int nrc);

/**
 * fp16 4×4 tile 矩阵乘法核：C[na][nb] = A[na][dim] × B[dim][nb]。
 * 以 4×4 子块为最小计算单元，使用 NEON vfmaq_f16 累加到 fp32。
 *
 * @param na               A 的行数（输出 C 的行数）
 * @param nb               B 的列数（输出 C 的列数）
 * @param dim              A 的列数 / B 的行数（内积维度）
 * @param a                矩阵 A，shape [na][dim]，元素类型 fp16
 * @param b                矩阵 B，shape [dim][nb]，元素类型 fp16

5.2 FP32 矩阵乘法优化

5.2.1 功能描述

对 FP32 矩阵乘法实现 SVE 4×4 tile kernel，利用 256-bit SVE 的 8-lane f32 并行能力，一次性计算 4×4=16 个点积。

5.2.2 核心算法

输入: A[M,K], B[N,K] (f32)
输出: C[M,N] (f32)

1. N 按 4 对齐, M 按 4 对齐主循环:
   - 初始化 16 个 svfloat32_t 累加器 (acc[0..3][0..3])
   - K 按 vl (向量长度) 分块:
     - 加载 A[j+0..3][k..k+vl] 到 j0..j3
     - 加载 B[i+0..3][k..k+vl] 到 i0..i3
     - acc[m][n] += j[m] * i[n]  (16 次 svmla_f32_m)
   - svaddv 水平求和写入 C
2. 尾循环: ggml_vec_dot_f32 fallback

5.3 Q8_0 量化矩阵乘法优化 (MMLA + Spack)

5.3.1 功能描述

对 Q8_0 (8-bit 量化) 矩阵乘法实现 MMLA (Matrix Multiply-Accumulate, i8mm 指令) + spack (数据打包) 的优化 kernel。这是优化工作中最复杂、性能提升最大的模块。

核心思路：

将 A、B 矩阵的 block_q8_0 结构数据重新打包 (spack) 为 MMLA 指令所需的内存布局

利用 SVE 的 smmla 指令 (8-bit × 8-bit → 32-bit，含符号) 实现矩阵乘累加

分块策略：Outer tile M=128 × N=64，K tile=2048，Micro tile 4×8

5.3.2 整体调用链

ggml_compute_forward_mul_mat()
    │
    ├─ 检查 Q8_0 是否提供专用 matmul
    │
    └─ compute_forward_mul_mat_one_chunk_matmul_kernel()
          │
          └─ type_traits[Q8_0].matmul
                │
                └─ matmul_q8_0_mmla_spack_b_g()
                      │
                      └─ matmul_q8_0_mmla_spack_b()
                            │
                            ├─ 外层 M/N/K 分块
                            ├─ pack A panel
                            ├─ pack B panel
                            └─ matmul_q8_0_mmla_8x8_b_micro_spack_neon()

5.3.3 Q80数据结构

Q8_0 每个 block 包含32 个 int8 量化值，1 个 fp16 scale，两个 Q8_0 block 做点积：

Σk (da × qa[k]) × (db × qb[k]) = (da × db) × Σk qa[k] × qb[k]

所以 micro-kernel 中分成两部分：

使用 SMMLA 计算 int8 点积，得到 int32。

将 int32 转成 FP32，再乘 A/B scale，累加到 FP32 C。
即：

int32_sum = Σ qa × qb
float_sum = int32_sum × scale_a × scale_b
C        += float_sum

5.3.4 数据打包 (Spack)

完整矩阵会被切成

A panel: M_BLK × K_BLK
B panel: N_BLK × K_BLK
C tile : N_BLK × M_BLK

同一个 A panel 在多个 N tile 之间复用，不再针对每个 N tile 重复打包 A。

M tile
  └─ K tile
       ├─ A 只打包一次
       ├─ N tile 0：打包 B0，计算 C0
       ├─ N tile 1：打包 B1，计算 C1
       └─ ...

A Pack (2 rows per group)：
A 打包：按 2 行一组。
例如：

A 第0行：a0[0..31]
A 第1行：a1[0..31]

每两行 A 的一个 Q8_0 block（每行 32 个 int8）交错打包成：

+0  ：第0/1行，a0[0..7]  + a1[0..7]
+16 ：第0/1行，a0[8..15] + a1[8..15]
+32 ：第0/1行，a0[16..23] + a1[16..23]
+48 ：第0/1行，a0[24..31] + a1[24..31]

这样每次加载 16B，前8B：第0行的 8 个 int8,后8B：第1行的 8 个 int8,这样正好组成 SMMLA 需要的 2 行 × 8 个 K 输入。

B Pack (4 rows per group)：
每四行 B 的一个 Q8_0 block 打包成：

+0   : 第0/1列，K 0..7
+16  : 第2/3列，K 0..7
+32  : 第0/1列，K 8..15
+48  : 第2/3列，K 8..15
+64  : 第0/1列，K 16..23
+80  : 第2/3列，K 16..23
+96  : 第0/1列，K 24..31
+112 : 第2/3列，K 24..31

5.4 Fused SDPA (FlashAttention v2 NEON)

5.4.1 功能描述

原始 llama.cpp Attention 由多个独立算子依次完成 QKᵀ、缩放、Mask、Softmax 和 PV 计算，需要反复读写大尺寸 scores 中间矩阵。

fused-cpp SDPA( Scaled Dot-Product Attention) 将这些步骤融合到一个专用算子中，通过分块计算、K/V packing、向量化 Mask 和在线 Softmax，减少中间数据搬运，提高缓存命中率和 SIMD 执行效率。该优化主要面向 F32、MHA 结构的 embedding 场景，并非替代所有 Attention 路径。

也就是说，改之前是把 attention 拆成多个 ggml tensor op，中间结果反复写回内存；改之后是把 QKᵀ、scale、mask、rowmax、softmax、乘 V 尽量合在一个 CPU 专用 kernel 里，按 tile 流式完成，减少中间张量和内存流量。

SDPA 本身就是O = softmax((QKᵀ * scale) + mask) V

对于 attention 来说，中间的 scores 形状通常是：
[batch, n_head, n_query, n_kv]

embedding 场景里经常是整段文本一次性算 embedding，不像 autoregressive decode 那样每次只生成一个 token，所以 n_query 和 n_kv 都可能比较大。这样 scores 矩阵会很大，被反复读写多次，CPU 上这类 workload 很容易从“算力瓶颈”变成“L2/L3/内存带宽瓶颈”。

Fused SDPA把原来图里的多个 op：

mul_mat(Q, Kᵀ)
scale
mask
softmax
mul_mat(scores, V)

融合成一个更专用的 C++/NEON/SVE kernel。

这个分支限制比较明显：主要面向 embedding path，要求 F32 Q/K/V/out，MHA only，也就是 n_head == n_head_kv。这说明它不是完整替代 llama.cpp 所有模型所有 attention，而是专门针对某些 embedding 模型常见结构做优化。

MHA（Multi-Head Attention）是每个 Head 都有自己独立的 K、V；

GQA（Grouped-Query Attention）是多个 Query Head 共用一组 K、V。

5.4.2 核心设计

集成方式：

通过 GGML_USE_FUSED_CPP_SDPA 编译宏控制

llama-graph.cpp 中的 build_attn_mha() 检测是否满足启用条件：

ARM64 平台

q/k/v 均为 F32 类型

MHA (n_head == n_head_kv)

无 MLA, 无 ALiBi, 无 attn_soft_cap

mask 为 F16/F32 contiguous 或无 mask

v->ne[0] % 8 == 0

满足条件时，构建 GGML_OP_FUSED_CPP_SDPA_EXT op，替代原生 flash_attn

推理流程：

llama-graph build_attn_mha()
    │
    ├─ 条件: use_fused_cpp_attn?
    │   ├─ YES → ggml_fused_cpp_sdpa_ext(ctx, q, k, v, mask, scale)
    │   │         → ops.cpp: ggml_compute_forward_fused_cpp_sdpa_ext()
    │   │            按 head 分区到线程
    │   │            └─ L == S 且 L%64==0 → 对角分块 (64×64 blocks)
    │   │            └─ else → 全矩阵调用
    │   │              └─ fused_cpp_sdpa_flash2_neon_l3kv_packqkv_pbf16pv_fp32_llamacpp()
    │   │
    │   └─ NO → 原生 flash_attn (flash_attn_ext)

对角分块优化：

当 L == S (prefill 场景) 且 L % 64 == 0 时，将注意力矩阵沿对角线划分为 64×64 的块，只计算上三角 (因果 mask 内) 的块，减少计算量。

NEON kernel 核心 (fused-cpp/fp32_packqkv/csrc/)：

QKV 在微内核内完成 pack+transpose，避免额外内存移动

L3-cache-aware KV 分块策略

fp32 内部精度，pb16 格式近似 softmax

所有 SIMD 操作通过内建函数实现，不依赖手写汇编

新增代码遵循 250 LOC 内聚原则，超标需要模块拆分

所有矩阵运算 kernel 遵循 restrict 指针注解

8.2 命名规范

遵循 llama.cpp 原生命名规范：

全局函数：ggml_* 前缀

静态函数：使用描述性小写+下划线

类型定义：_t 后缀

kernel 函数：明确标注数据类型和 tile 尺寸

9 构建指导

9.1 工程结构

CMakeLists.txt                # 顶层构建
compile.sh                    # 一键编译脚本
test_correctness.py           # 端到端正确性验证
ggml/
├── include/ggml.h            # SDPA ext op 定义
└── src/ggml-cpu/             # CPU 后端优化 kernel
src/
└── llama-graph.cpp           # fused SDPA 条件判断

9.2 编译说明

编译所需依赖如下：

GCC/G++ >= 15.2.0 (需支持 armv8.6-a+dotprod+i8mm+sve)

cmake >= 3.20

ninja (可选，推荐)

git

9.3 构建方法

# 1. 获取源码后进入项目根目录

# 2. 选择编译方式
# 方式 A: 使用一键脚本
bash compile.sh build-fused-sdpa

# 方式 B: 手动 CMake
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release \
      -DGGML_CPU_ARM_ARCH="armv8.6-a+dotprod+i8mm+sve" \
      -GNinja ..
ninja ggml-cpu llama-embedding llama-bench llama-server

# 3. 运行验证
./bin/llama-embedding -m model.gguf -p "test"
