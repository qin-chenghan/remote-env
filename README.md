# remote-env

给 Agent 用的远程服务器协作仓。Agent 不能直连服务器，通过本仓与用户协作：

**Agent 写命令 → 用户在服务器上执行 → 用户把结果 push 回来 → Agent 读取分析。**

仓库是公开的，服务器上匿名 `clone` / `pull` 即可，无需配置凭据。

## 目录结构

```
remote-env/
└── 184/              # 以服务器 IP 末段命名，如 184、32、84
    ├── cmd.sh        # 该机器的待执行命令集，Agent 每次覆盖
    ├── NOTES.local.md # 该机器的本地笔记（.gitignore，不入库）
    └── tmp/          # 执行结果日志，按时间戳落盘
```

每台服务器一个独立目录、一个独立 `cmd.sh`，互不影响，可以同时给多台机器挂命令。
目录内还可放该机器的环境说明等文件。

## 工作流

1. **Agent 写命令**
   修改目标机器目录下的 `cmd.sh`（如 `184/cmd.sh`），把命令写进标记区间。
   每次整体覆盖，不新建脚本。

2. **用户在服务器上执行**
   ```bash
   git pull && bash 184/cmd.sh
   ```

3. **用户 push 回结果**
   ```bash
   git add -A && git commit -m "184: 20261106-143000" && git push
   ```

4. **Agent 读取**
   结果在 `<server>/tmp/<时间戳>.log`，Agent 直接读最新文件。

## cmd.sh 约定

- 脚本从自身所在目录推断服务器名，服务端无需传参，路径与仓库布局无关。
- **命令必须写在标记区间内**：区间内的 stdout/stderr 由 `tee` 自动落盘，末尾记录整体 exit code。
- 输出到文件的命令（如 `nvidia-smi -q > x.txt`）不会自动入日志，需要时在区间末尾 `cat` 出来。
- `set -x` 已开启，日志同时包含命令本身和输出，可独立阅读。
- 日志按时间戳保存、不覆盖，便于对比历次执行。
- 只写非交互式命令，避免长时间阻塞；需要 `sudo` 时确认该服务器已免密。
- 命令执行完脚本会打印日志路径。
